# EAC Study 2 — Frozen Confirmatory Protocol

## Purpose
Study 1 established the internal logic of EAC in purpose-built synthetic environments. Study 2 is a stronger bridge test using an **actual pretrained causal language model**, a **frozen base model**, **LoRA adapters**, and a **programmatic pass/fail verifier**.

The primary question is:

> After external exposure has stopped, can internally initiated candidate generation, verification, and LoRA consolidation improve held-out behavior more than literal replay or unchecked self-training?

This is intentionally narrower than a claim of autonomous self-improvement.

## Important terminology
During the EAC interval there are **no new environmental observations and no corrective target labels**. However, the programmatic verifier returns pass/fail. That is new **evaluative information**. Therefore the study must not be described as learning with “zero new information.”

## Fixed model
- `HuggingFaceTB/SmolLM2-135M-Instruct`
- Frozen pretrained base weights
- PEFT/LoRA on available attention/MLP projection modules
- LoRA rank = 8, alpha = 16

The model may be changed only if the smoke test fails for a software/compatibility reason, and that change must happen **before** the confirmatory run.

## Task construction
Each matched seed defines two hidden 4-class rule tasks, `ZORP` and `MIRA`.

The label is generated by a seed-specific modular rule followed by a seed-specific class permutation. The model never receives the formula. During external exposure it receives labeled examples.

For ZORP, operands are divided into two contexts (0–7 and 8–15):
- External exposure uses only same-context pairs.
- A within-context adaptation pool is unseen during exposure.
- A cross-context adaptation pool contains low/high or high/low recombinations never shown externally.
- Held-out evaluation pairs are disjoint from all adaptation pools.

MIRA is a second hidden task used to quantify retention during later ZORP adaptation.

## Conditions
All non-baseline adaptation conditions use the same LoRA rank and fixed number of adapter optimizer steps.

1. **No update** — no endogenous parameter update.
2. **Replay** — reuses externally labeled ZORP examples.
3. **Unchecked hard self-training** — chooses high-entropy unseen candidates and trains on the model’s own sampled label without verification.
4. **Validated uniform EAC** — uniformly chooses unseen candidates; sampled model labels are kept only when a pass/fail verifier approves them.
5. **Validated hard EAC** — prioritizes high-entropy unseen candidates; sampled labels are kept only after pass/fail verification.
6. **Validated dream/recombination** — constructs cross-context combinations from operands previously seen only in separate contexts; self-generated labels are consolidated only if verified.
7. **Validated hard EAC + anchor replay** — same as validated hard EAC, but a fixed fraction of the update pool is replaced with old MIRA anchors to test retention.

### Verifier constraint
The verifier is allowed to answer only **pass/fail** for a model-proposed class. It must never inject the corrected class into the training set. A training label enters EAC only when the model itself proposed that label and the verifier accepted it.

## Confirmatory seed block
12 matched seeds:

`41001 + 97*i`, for `i = 0,...,11`.

The smoke seed (`91001`) is outside this block.

## Primary endpoints
- `zorp_acc`: held-out target accuracy over within- and cross-context examples.
- `cross_acc`: held-out accuracy specifically on cross-context compositions.
- `mira_acc`: retained accuracy on the old MIRA task.

## Six prespecified directional hypotheses
For every hypothesis, the directional form is `H0: mu_treatment <= mu_control`, `HA: mu_treatment > mu_control`.

- **R1 — Validated EAC vs replay:** validated hard EAC has higher `zorp_acc` than literal replay.
- **R2 — Validation necessity:** validated hard EAC has higher `zorp_acc` than unchecked hard self-training.
- **R3 — Endogenous gain:** validated hard EAC has higher `zorp_acc` than no update.
- **R4 — Recombination:** validated dream/recombination has higher `cross_acc` than literal replay.
- **R5 — Anchor retention:** validated hard EAC + anchor replay has higher `mira_acc` than validated hard EAC without anchors.
- **R6 — Selection policy:** validated hard EAC has higher `zorp_acc` than validated uniform EAC.

## Statistics
Across the 12 matched seeds:
- one-sided paired t-test for each primary hypothesis;
- mean paired difference;
- two-sided 95% CI for the paired difference;
- paired Cohen dz;
- Wilcoxon signed-rank sensitivity test;
- wins/ties/losses and one-sided sign test;
- Holm family-wise correction across the six primary hypotheses.

Reject a primary null only when its Holm-adjusted p-value is < .05.

Failure to reject does **not** prove the null.

## Secondary diagnostics — not additional primary hypotheses
Report without converting them into new confirmatory claims:
- within-context accuracy;
- ZORP NLL, Brier score, and entropy;
- candidate acceptance rate;
- first-attempt verifier pass rate;
- unchecked pseudo-label error rate (audit only, never exposed to training);
- LoRA adapter norm;
- adaptation wall-clock time;
- target-retention trade-off for the anchor condition.

## Confirmatory integrity rules
1. Run `--preset smoke` first only to check dependencies, model loading, and file generation.
2. If smoke fails technically, fix software before confirmatory execution.
3. Do not tune learning rates, seed count, candidate budget, hypothesis definitions, or task splits based on confirmatory outcomes.
4. Run `--preset confirmatory` once.
5. If interrupted by hardware/software failure, rerun with the same output directory and `--resume`; completed seeds are skipped.
6. Return the complete result ZIP, including `metrics.csv`, `hypothesis_tests.csv`, `run_config.json`, `SUMMARY.txt`, `candidate_audit.csv`, and `plots/`.
